# Research: Tick-off UI/UX evaluation rubric (Android app audit)

## Visual hierarchy and layout
P1. De-emphasise secondary content to emphasise the primary. — "De-emphasize to emphasize" [Refactoring UI].
P2. Treat hierarchy as everything; not all elements are equal. — "Not all elements are equal" [Refactoring UI].
P3. Remove irrelevant or rarely-needed content. — "Interfaces should not contain information that is irrelevant or rarely needed." [NN/g heuristics].
P4. Place controls where they effect change. — "Put interface elements where they effect change." [Learn UI Design].
P5. Work in black and white first, then add colour with purpose. — "design black and white first" [Learn UI Design].
P6. Define the optimal layout and visual hierarchy for each screen. — "What's the optimal layout and visual hierarchy for each screen?" [CareerFoundry].
P7. Use light-from-the-sky shading and shadows to convey depth. — "Light comes from the sky" [Learn UI Design].
P8. Don't overlook empty states. — "Don't overlook empty states" [Refactoring UI].

## Typography
P9. Establish a type scale. — "Establish a type scale" [Refactoring UI].
P10. Use good fonts. — "Use good fonts" [Refactoring UI].
P11. Keep line length in check. — "Keep your line length in check" [Refactoring UI].
P12. Set line-height proportionally. — "Line-height is proportional" [Refactoring UI].
P13. Ensure every font face used is a good one. — "Use only good fonts" [Learn UI Design].

## Colour and contrast
P14. Give text consistent contrast against its background. — "Text needs consistent contrast" [Refactoring UI].
P15. Don't use grey text on coloured backgrounds. — "Don't use grey text on colored backgrounds" [Refactoring UI].
P16. Define your shade palettes up front. — "Define your shades up front" [Refactoring UI].
P17. Don't rely on colour alone. — "Don't rely on color alone" [Refactoring UI].
P18. Add colour last and only with purpose. — "Add color last, and even then, only with purpose." [Learn UI Design].

## Spacing and alignment
P19. Start with too much white space / double your whitespace. — "Start with too much white space" [Refactoring UI].
P20. Establish a spacing and sizing system. — "Establish a spacing and sizing system" [Refactoring UI].
P21. Avoid ambiguous spacing. — "Avoid ambiguous spacing" [Refactoring UI].
P22. Align with readability in mind. — "Align with readability in mind" [Refactoring UI].

## Consistency and platform convention
P23. Maintain internal and external consistency; follow platform conventions. — "Users should not have to wonder whether different words, situations, or actions mean the same thing. Follow platform and industry conventions." [NN/g heuristics].
P24. Speak the user's language and follow real-world conventions. — "The design should speak the users' language." [NN/g heuristics].
P25. Match each platform's native patterns (Android FAB, back gesture). — "navigating back is much simpler: for Android 10 and newer, simply swipe from either side of the screen in" [Learn UI Design].
P26. Supercharge the platform defaults. — "Supercharge the defaults" [Refactoring UI].
P27. Choose the right control; don't default to dropdowns. — "dropdowns are pretty much the worst control" [Learn UI Design].

## Feedback and system status
P28. Keep users informed of system status with timely feedback. — "The design should always keep users informed about what is going on, through appropriate feedback within a reasonable amount of time." [NN/g heuristics].
P29. Present feedback as quickly as possible. — "Present feedback to the user as quickly as possible (ideally, immediately)." [NN/g heuristics].

## Error prevention and recovery
P30. Prevent errors before they occur, with good defaults and constraints. — "the best designs carefully prevent problems from occurring in the first place" [NN/g heuristics].
P31. Confirm before committing to destructive actions. — "present users with a confirmation option before they commit to the action" [NN/g heuristics].
P32. Write plain-language error messages that state the problem and suggest a fix. — "Error messages should be expressed in plain language (no error codes), precisely indicate the problem, and constructively suggest a solution." [NN/g heuristics].

## User control and freedom
P33. Provide a clearly marked emergency exit from unwanted actions. — "They need a clearly marked 'emergency exit' to leave the unwanted action without having to go through an extended process." [NN/g heuristics].
P34. Support Undo and Redo. — "Support Undo and Redo." [NN/g heuristics].

## Recognition over recall
P35. Make elements, actions and options visible to cut memory load. — "Minimize the user's memory load by making elements, actions, and options visible." [NN/g heuristics].
P36. Offer in-context help instead of a tutorial to memorise. — "Offer help in context, instead of giving users a long tutorial to memorize." [NN/g heuristics].
P37. Don't hide important functionality for tidiness. — "avoid anything that hides important stuff, because obvious always wins" [Learn UI Design].

## Accessibility
P38. Keep accessibility compatible with attractive design. — "Accessible doesn't have to mean ugly" [Refactoring UI].
P39. Meet minimum tap-target sizes (Android 48x48 dp). — "Minimum tap target size … 48x48 dp" [Learn UI Design].
P40. Ensure text is easy to read. — "If a website's information is hard to read or doesn't answer users' key questions, they leave." [NN/g usability].

## Usability testing and research
P41. Judge usability by learnability, efficiency, memorability, errors, satisfaction. — "Usability is defined by 5 quality components" [NN/g usability].
P42. Test users individually and let them solve problems alone. — "It's important to test users individually and let them solve any problems on their own." [NN/g usability].
P43. Test with about five users and iterate. — "testing 5 users is typically enough" [NN/g usability].
P44. Start testing early; don't defer it to the end. — "Don't defer user testing until you have a fully implemented design." [NN/g usability].
P45. Understand users through research and experimentation. — "UX designers work closely with UI designers, UX researchers, marketers, and product teams to understand their users through research and experimentation." [UserTesting].
P46. Design human-first, covering the whole experience, not just the UI. — "user experience design is a human-first way of designing products." [CareerFoundry].

## Documentation and help
P47. Make help documentation easy to search. — "Ensure that the help documentation is easy to search." [NN/g heuristics].
P48. Present documentation in context when the user needs it. — "present the documentation in context right at the moment that the user requires it." [NN/g heuristics].

## Consensus (stated by at least two sources)
C1. Double the whitespace (P19) — [Refactoring UI] + [Learn UI Design].
C2. Use good fonts (P10, P13) — [Refactoring UI] + [Learn UI Design].
C3. Design the whole experience, not just UI surfaces (P46) — [CareerFoundry] + [UserTesting].
C4. Follow platform and real-world conventions (P23, P24) — [NN/g heuristics] + [Learn UI Design].
C5. Keep required information visible rather than hidden (P35, P37) — [NN/g heuristics] + [Learn UI Design].
